# 食见 · 操作与演示指南

这是一份竞赛原型：在本地展示食品标签、按勾选项执行固定规则、对比三款样例食品。无需后端、云开发或大模型。所有数据均为虚构样例，结果仅作消费参考。

## 1. 在电脑上打开并运行

本次已在微信开发者工具 **2.02.2609250 Stable** 完成导入、编译、实际二维码图片识别和红色预警验证，也已成功生成手机预览二维码。

1. 解压源码；如果从 GitHub 下载，先解压 ZIP。
2. 打开微信开发者工具，登录后点击「导入（Import）」。
3. 选择含有 `project.config.json` 的项目根目录，**不要选择里面的 `miniprogram` 文件夹**。
4. 当前配置保存了本次实测的测试号 AppID，同一账号可直接使用。其他微信账号导入时，点击「测试号（Test Account）」选择工具分配的测试号。
5. 项目类型选择「小程序」，云服务选择「不使用云服务（Use no cloud service）」，点击「创建（Create）」。
6. 进入项目后点击右上方「编译」。模拟器显示「扫码展示」，底部有「规则判别」「食品对比」。

直接编译即可，不需要「构建 npm」、安装 Node.js、启动网页预览或配置服务器。开发者工具不同版本的按钮位置可能略有变化。

## 2. 三分钟演示流程

### 第一步：展示食品标签

打开「扫码展示」→ 点击「扫一扫食品标签」→ 在文件窗口选择 [peanut-crisp.png](qrcodes/peanut-crisp.png)。页面显示花生牛奶酥、四项营养数值和过敏原，来源应为「扫码结果」。

二维码图片内是完整中文 JSON，程序通过 `wx.scanCode` 读取，再进行本地校验和展示。

### 第二步：演示重点——纯规则预警

打开「规则判别」，先取消上次演示保留的勾选项，再按下表操作。点击「扫码并判断」后选择对应图片。

| 勾选项 | 测试二维码 | 预期结果 |
| --- | --- | --- |
| 花生、糖尿病 | [花生牛奶酥](qrcodes/peanut-crisp.png) | 红色「过敏原预警」，并列出糖 22g 超过 15g 的「谨慎食用」提示 |
| 牛奶 | [原味酸奶](qrcodes/plain-yogurt.png) | 红色牛奶过敏原预警 |
| 高血压 | [即食鸡胸肉](qrcodes/chicken-breast.png) | 「谨慎食用」，原因是钠 680mg 达到 600mg 演示阈值 |
| 糖尿病 | [原味酸奶](qrcodes/plain-yogurt.png) | 「未触发已选规则」；不表示适合所有人食用 |

多个条件命中时全部列出；有过敏原命中时以红色预警为主。点击「我知道了，查看详情」关闭弹窗，结果仍保留在页面内。

如果现场不方便扫码，可点击食品样例，或点击「粘贴 JSON」粘贴 [同名 JSON 文件](qrcodes/)的内容。这两个入口使用同一套解析和规则，但报告中的“扫码验证”应使用实际图片识码步骤。

### 第三步：展示并排对比

切换「食品对比」。三款样例统一按每100克展示钠、糖、脂肪、蛋白质及过敏原。下方展示分级边界，方便解释颜色来源。

## 3. 颜色和判断规则

所有营养值均按**每100克**计算；钠为 **mg**，其他三项为 **g**。

| 营养素 | 绿 | 橙 | 红 |
| --- | --- | --- | --- |
| 钠 | ≤120 | >120 且 <600 | ≥600 |
| 糖 | ≤5 | >5 且 <15 | ≥15 |
| 脂肪 | ≤3 | >3 且 <20 | ≥20 |
| 蛋白质 | ≥12 | ≥6 且 <12 | <6 |

营养颜色与个人规则是两套判断。例如糖刚好为15g时显示红色，但糖尿病提示的触发条件是 **>15g**；高血压演示条件是钠 **≥600mg**。过敏原按文字精确匹配，如「花生」不会自动匹配其他同义词。

部分阈值参考 GB 28050 营养声称条件，**整套颜色和慢性病提醒均是原型自定义规则**。请保留页面的“仅作消费参考”说明。标准版本、来源及边界细节见 [README](../README.md#gb-28050-表述说明)。

## 4. 修改样例及重新生成二维码

日常演示无需修改源码，也无需重新生成图片。需要改样例时：

1. 打开 [miniprogram/data/foods.js](../miniprogram/data/foods.js)，修改现有三条数据的名称、营养值或过敏原。
2. 保留每条数据唯一的 `id`，`basis` 必须为 `'100g'`。营养值填写数字，例如 `sugar: 22`，不能写成 `'22g'`。过敏原未列出时使用 `[]`。
3. 保存后重新编译。页面样例和对比表会读取新数据，但**旧二维码仍包含旧数据**。
4. 如需同步二维码，在安装有 Node.js、Python 3、Pillow 和 reportlab 的环境中，从项目根目录运行：

```bash
python3 tools/generate_qr.py
```

若 Node.js 不在命令搜索路径，可指定：

```bash
python3 tools/generate_qr.py --node /你的路径/node
```

脚本更新 `docs/qrcodes/` 内的同名 PNG、JSON、汇总图和清单。当前汇总图按三款食品设计。生成后重新用小程序扫新 PNG，检查食品名和数值；不要沿用旧截图作为新数据的验证证据。

仅在缺少生成依赖时，可在单独的 Python 虚拟环境安装 `Pillow` 和 `reportlab`。**使用交付的二维码和运行小程序本身均不需要这些依赖。** 有 Node.js 时还可在根目录执行 `npm test` 运行自动测试。

## 5. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 导入后找不到页面或编译失败 | 确认导入的是含 `project.config.json` 的根目录，项目类型为小程序；使用当前稳定版开发者工具 |
| AppID 或权限提示 | 当前 AppID 来自本次账号的测试号；换账号时在导入界面重新选择「测试号」，不要填写其他人的 AppID |
| 扫码提示不是有效 JSON | 选择 `docs/qrcodes/` 中的单张食品 PNG；普通商品条形码、网址或小程序入口码都不符合本原型数据格式 |
| 二维码识别不到 | 使用原始单张 PNG，保留白边，避免截图裁掉边缘或反复压缩；不要优先扫描三张拼在一起的汇总图 |
| 没有触发预期预警 | 核对当前勾选项、食品来源及单位；糖尿病条件是糖大于15，等于15不触发；多个勾选项会共同参与判断 |
| 重新编译后勾选仍存在 | 这是本地保存的关注项；逐项取消，或通过开发者工具清除本地缓存后重新编译 |
| 修改样例后扫码还是旧数值 | 重新生成二维码，或更新 JSON 后使用「粘贴 JSON」；只改源码不会改变已有 PNG 的内容 |
| 页面显示「标签未列出」 | 对应 `allergens: []`，仅表示测试标签未提供过敏原，不代表食品没有过敏风险 |

## 7. 在手机微信中查看，以及分享给别人

### 自己在手机上预览

1. 在开发者工具确认编译正常，点击右上方「预览（Preview）」。
2. 工具生成预览二维码后，使用与开发者工具登录账号一致的手机微信扫一扫，按提示打开小程序。
3. 打开后，进入小程序内的「扫码展示」或「规则判别」，再扫描食品测试二维码。可在电脑上显示单张食品 PNG，让手机对着电脑屏幕扫码。

当前项目使用测试号，已实际生成预览二维码。预览码有有效期，过期后重新点击「预览」生成；测试号的预览和权限以工具实际提示为准。**本次交付已验证开发者工具图片识码和预览码生成，尚未验证手机端打开和摄像头扫码**。

### 给同学或评委独立体验

当前测试号不支持上传，不能直接作为可上传体验版的注册小程序账号。也不要假定把自己的预览二维码转发后，任意微信账号都能打开。

需要多人独立测试时，应使用你自己注册并有开发权限的小程序 AppID：

1. 在开发者工具中将项目配置为该 AppID，重新编译并检查。
2. 使用工具「上传」代码。
3. 管理员进入微信公众平台，在版本管理中将上传的开发版本设为体验版。
4. 在「管理 → 成员设置 → 体验成员」中添加需要体验的微信用户，再分享平台生成的**体验二维码**。

体验版只面向获授权的体验成员；正式版面向公众，需要走平台正式发布流程。注册、权限、审核及备案等要求请按对应账号后台当前提示办理。当前源码交付没有替你上传体验版或正式发布。

版本与体验成员概念可参阅 [腾讯官方说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/App-Publishing/Mini-Program)；其中包含其他产品的发布操作，使用本项目无需安装该产品。微信官方入口：[开发工具测试号说明](https://developers.weixin.qq.com/miniprogram/dev/devtools/sandbox.html)、[发布流程说明](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)。

### 两种二维码不要混淆

| 类型 | 谁生成 | 用途与扫描位置 |
| --- | --- | --- |
| 小程序预览码／体验码 | 微信开发者工具或微信公众平台 | 用手机微信扫一扫，打开小程序；受账号和成员权限限制 |
| 食品标签测试码 | 本项目 `docs/qrcodes/` 内的 PNG | 已打开小程序后，点击页面内的扫码按钮读取食品 JSON；不是小程序入口 |

GitHub 私有仓库用于保存和交付源码，只有获授权的 GitHub 账号能够访问。仓库链接不会直接在微信中运行小程序，也不会自动生成小程序入口码。只需向评委展示成果时，可以直接分享本指南第6节中的截图，并在现场使用开发者工具演示。
